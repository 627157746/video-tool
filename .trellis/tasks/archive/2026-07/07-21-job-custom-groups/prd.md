# PRD: 任务自定义分组与按分组筛选

## Goal

让用户能为 Job 指定自定义分组名称，并在任务列表按分组筛选，便于整理多条下载/录制/导入任务。

## User Stories

1. 作为用户，我可以为任意任务设置或清除一个自定义分组名称。
2. 作为用户，我可以在创建任务时（可选）指定分组。
3. 作为用户，我可以在任务列表按「全部分组 / 某个分组 / 未分组」筛选。
4. 作为用户，我可以在列表卡片与详情中看到当前分组。

## Scope (MVP)

- Job 持久化字段 `group: Option<String>`（自由文本，非固定枚举）。
- 旧 `source.json` 缺字段时视为未分组。
- `JobListItem` 暴露 `group`，便于列表筛选与展示。
- 命令 `update_job_group`：运行中的任务禁止修改（与标题一致）。
- 创建三类 Job 请求可选 `group`。
- 前端：
  - 列表工具区：分组筛选芯片（全部 / 各已用分组名 / 未分组）。
  - 搜索仍可用；与分组筛选取交集。
  - 卡片展示分组 pill（有值时）。
  - 创建表单可选分组输入。
  - 详情「来源概览」可编辑并保存分组。

## Non-goals

- 独立的分组管理后台（重命名全量、排序、颜色、图标）。
- 多标签（tags）或多分组归属。
- 服务端预定义分组目录。
- 跨工作区共享分组字典。

## Acceptance Criteria

1. 旧任务无 `group` 字段可正常加载与列表显示，筛选「未分组」可见。
2. 设置分组后刷新/重启仍保留；清除后回到未分组。
3. 列表可只显示某一分组；切换「全部」恢复。
4. 分组筛选 + 搜索同时生效。
5. 运行中任务不能改分组；空闲时可改。
6. 创建时可写入分组；不填则未分组。
7. `pnpm typecheck`、`pnpm build`、相关 Rust 检查通过。

## Open Decisions (locked for MVP)

- 分组值：trim 后的自由字符串；空字符串等价于清除（null）。
- 不区分大小写做筛选匹配（展示保留用户输入的原始大小写）。
- 分组列表来自当前工作区任务的 distinct 非空分组名，按名称排序。
